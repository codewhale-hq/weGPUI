# Component acceptance inventory — WeUI 2.6.26

Source/API inventory reconciled on 2026-10-25. Columns API…a11y describe source support;
*Verified* and *Open* distinguish sampled runtime evidence from remaining acceptance work
(see STATUS "Behaviour by family" and the linked receipts). A row is
**accepted** only when every applicable column has runtime evidence on macOS, Windows and Linux,
in light, dark and care mode, plus screen-reader acceptance. **No row is accepted yet.**

The second Linux batch starts at `9c4515c`, with the separately green vertical-form fix
`a3ce3af` integrated. Each receipt identifies its executable and source snapshot; earlier
samples are not promoted to later source. Approved local GPUI/AccessKit compatibility copies
address cache signals, state forwarding and X11 origins. The final source, including the
checkbox/caret review corrections, passed formatting, all-target build, 47 unit tests (one
ignored doctest), strict Clippy and strict rustdoc on Rust 1.98.1, locked/offline where
applicable ([gate receipt](receipts/component-contracts-20261025/README.md)). Article light/dark
visual review, corrected checkbox eight-mode callback/interior-pixel checks and final
Outlined/FilledGrey caret/action pixel reviews pass. This does not qualify another desktop host.

Legend: *Focus* — keyboard focusable. *Keys* — `custom` = component key handling,
`click` = GPUI click activation on Enter/Space. *Reveal* — registers with
`scrolling::FocusScroll` (`overlay` = lives in a Modal, which manages its own focus).
*Priority* — P1 blocks desktop developer preview, P2 needed for "entire WeUI", P3 static or
presentational.
