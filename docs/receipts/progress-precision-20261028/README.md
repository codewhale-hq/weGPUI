# Fractional progress accessibility probe

At clean weGPUI HEAD `04b006ac1094bb72e276b30dca077830f7bdebe7`, `Progress::value` draws the supplied clamped fraction but rounded both its accessibility numeric value and text. On a 400-pixel track, the 0.4% baseline paints two green pixels but Linux AT-SPI reports 0; 49.6% paints 198 pixels but reports 50. A 0.125% bar reports 0 even though its supplied value is nonzero (at scale 1 this particular fill is below a whole painted pixel). Existing progress receipts covered integer values.

The recorded `progress.patch.gz` decompresses to a patch with SHA-256 is `abc80d10000d3feeaf46541ca3ec7ff8d786ac24904036b2b5b4f0a86a458303`. It exposes the clamped `f32` value as `f64`, formats the same `f32` as a percentage for value text, and normalizes negative zero; it changes no paint geometry. `git apply --check` and `rustfmt --check` passed. Source snapshots before/after build and capture match (SHA-256 `758f500f79f47756d04533bfed39549bf609cdaa5c3f07c6b2e4635ea4bf4888`). The paired native binaries SHA-256 are `8928f0d81d3a81caceb2cd2f41de685b831ccbd6036d5f845571b1e6fd77a0d3` (baseline) and `0aae14a92efef0508ea54911991bf04ac20a67cbe37f1ded3dbd673c538a06f3` (candidate).

In Linux X11 with actual AccessKit/AT-SPI, `evaluate.py` passed all ten numeric cases: fractional, integer, zero, negative zero, NaN, positive infinity, below zero and above 100. Candidate values equal the stored `f32` converted to `f64`; 0.4 and 49.6 thus appear as `0.4000000059604645` and `49.599998474121094`. All bounds and bar-region pixels matched; the complete paired screenshots are byte-identical (SHA-256 `a98b3d0aeb056365e8054300e87f4f60516f8a16f4391ec8e161b289eaff4e47`). Results and raw snapshots are retained here. The initial standalone pixel-inspection command lacked the Debian Pillow path and failed; rerunning with `PYTHONPATH=/usr/lib/python3/dist-packages` succeeded.

The AT-SPI adapter returned null for value text both before and after, so the candidate text format is source-reviewed but not proven through this bridge. This is not a screen-reader speech, macOS, Windows or full-theme acceptance result. Build commands ran under the shared lock; the candidate is an artifact copy, not a product commit.

The final product source is identified in `product-source.json`. The macOS ARM64 library suite passed 54 tests and strict all-target Clippy. The Windows x64 GNU all-target cross-check passed with the [recorded wrapper](../windows-cross-20261028/README.md); it did not execute Windows tests. Five website inventory tests and selected root/project-prefix browser checks passed.
