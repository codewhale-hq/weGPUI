# Explicit font fallback preservation: bounded Linux probe

Bounded evidence; not full platform or browser parity. The high-level change retains a caller's explicit fallback list when its requested primary family cannot be loaded. It keeps the existing default family's style, weight and features, and retries the pre-existing unconfigured default stack if every configured attempt fails. When the requested family loads, or no list was provided, the existing path remains in effect.

The proposed exact patch is `product.patch`, SHA-256 `b5660127c688cdd5384a6116aa0f9ae560934ff24c3b9ea474526869254980a7`. Its base `vendor/gpui_pre/src/text_system.rs` SHA-256 is `459859b89aa7610d6293f2dd4344e971b5ce50509efdb40a95b60bf790e3ed6be`. The container had no IBM Plex Sans; `.SystemUIFont` mapped to that absent family and then to the existing default stack.

The 4-text, 2-width fixture exercised Arabic, Hebrew, Latin and emoji. `python3 evaluate.py` passes: all eight absent-primary rows with the preservation enabled match the installed-primary explicit-fallback control in row boundaries, widths, glyph IDs, positions and clusters; installed-primary before/after and absent-primary/no-list before/after outputs are identical. Arabic and Hebrew glyph selection and widths change when the requested fallback is carried through; Latin and emoji examples do not. As a separate control, an intentionally unavailable fallback produced unchanged shapes and widths in all eight rows without panic. Output JSON and SHA-256 values remain in this directory. The `WEGPUI_PRESERVE_EXPLICIT_FALLBACKS` environment variable is only an A/B fixture gate and is not part of the product patch.

This is Linux source/build and bounded native shaping evidence, not proof of visual parity or a general emoji policy. The fallback-only loader and cache-role experiment was not used in this fixture. macOS and Windows backends were inspected statically but have not been runtime-tested for this change. Windows caches full font selections including the fallback list, but its native face cache is keyed by face identity and can associate multiple configurations of the same face; Windows native testing is still needed to establish that behavior. User authorization limits Windows work to builds/tests only. The configured-load failure retry is present in the patch, but the unavailable-family fixture only exercises Linux's handling of a missing fallback, not every possible platform load error.

The final product source is identified in `product-source.json`; the patch is gzip-compressed to preserve exact diff bytes. The macOS ARM64 library suite passed 54 tests and strict all-target Clippy. The Windows x64 GNU all-target cross-check passed with the [recorded wrapper](../windows-cross-20261028/README.md); this is type checking, not native Windows execution. Five website inventory tests and selected root/project-prefix browser checks passed.
