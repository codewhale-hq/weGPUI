# Dictionary line-breaking experiment — local qualification, 2026-10-28

A local experimental line-breaking implementation improved the tested Linux row comparisons against Chromium: 393 of 420 matched, compared with 311 for the current provider. Among those comparisons, 82 improved and none worsened. The experiment has not shipped, and the remaining rendering and text-editing cases still need investigation. These are comparisons of shaped row geometry, not 420 screenshot comparisons or a claim of platform-wide parity.

The 23 remaining leading-mark row mismatches have candidate break streams equal to the exact pinned ICU oracle, pointing downstream to shaping, layout and/or font behavior; the specific cause is not yet established. Four remaining edge rows involve Myanmar virama: the experimental grapheme guard intentionally suppresses a valid ICU opportunity inside an original grapheme. Removing that guard experimentally improved some row comparisons, but row-local caret snapping can then put the caret inside the original full-document grapheme, and the native glyph clusters cannot always expose the requested break. This is an unresolved editing and shaping issue, not proven safe from a boundary match.

The exact reference is Chromium-pinned ICU 78.2 revision `19dfb44a62ae60ce6b0060de8c0cef5d5c527177`, original `icudtl.dat` SHA-256 `02a01b3188b6a41a756f7322fdb5e6b5ca6573b327b01dfc8ed662d571a6f769`. The decoded pinned line rules (`line.brk` SHA-256 `69e557c954e18af5be4365ce39050d42eabfbf63d3b8986659e6e1bc16271805`) agree with a modified 78.2 package with four SA dictionaries removed on 5,000 fuzz and 12,000 word rule streams; that modified package retains CJK dictionaries and shares the source/data, so it is not an independent general conformance oracle. The full candidate matches 4,477/5,000 independent synthetic fuzz streams against the unmodified pinned oracle; the fresh 32-input corpus matches 32/32 but uses shared CLDR provenance, and is not independent natural-language acceptance. Thirty bounded mandatory-break text-stream cases matched, including CRLF controls; this does not establish editor behavior.

Python-regex classification of the same 5,000 fuzz cases found 900 baseline and 98 candidate strings with at least one non-grapheme boundary, with zero newly introduced non-grapheme offsets by the candidate and 859 removed. The host Unicode version/classification can differ from the product; this does not prove caret, selection, IME, or emergency-wrap safety.

## Cost and integration gates

A separate offline debug executable copied the exact shipped provider and Khmer/Lao blobs. Their SHA-256 values match commit `1c633f9c1d24cf0180e2dd9336f5d05d2f4a6007`: provider `c5d3cca5d81a163f33a50ad4ee28e2811995a4834ae5c8d510b939f55272bd72`, Khmer `7f56e4358372b19fe7b4aa15bee71e7f06e3d48f407c2c5973e5122043e3a214`, Lao `4274ef25980a4d89dc6de38bade1ee3f67239e489178baf35d4bff971badc3a4`. Five alternating-order samples include startup, JSON, and two provider calls; the candidate's baseline output matched the standalone shipped provider in each sample. At 25,600 ASCII codepoints medians were 14.92 ms shipped versus 15.94 ms experimental; at 7,168 Thai codepoints 16.11 versus 36.50 ms; at 4,096 alternating Thai/Lao codepoints 14.03 versus 21.16 ms. These debug-process figures are not release-mode or UI-frame measurements; Thai overhead needs profiling before integration. Samples and hashes are in `performance-shipped-result.json`.

The extra Thai/Myanmar trie bytes total 682,242 and pinned rule tables 65,724, or 747,966 raw bytes beyond the existing Khmer/Lao payloads; this is not a measured linked-binary or resident-memory delta. The rule loop has a per-text iteration budget and falls back to shipped behavior when exhausted; other text traversal, dictionary work, allocations, sorting and deduplication scale with input, and there is no whole-pipeline latency or memory limit. Budget fallback visibility and correctness still need validation on adversarial long inputs and real workloads.

Promotion requires independent review, reproducible generation and licensing (including the full Myanmar BSD terms), release profiling against shipped behavior, work-budget/fallback tests, and native row/font/shaping verification. Text layout and editing need end-to-end checks for original-document grapheme boundaries, caret and selection, IME, mixed scripts and bidi, styled runs, hard breaks, wrapping, line clamp and caching. Linux and macOS runtime checks and the authorized Windows build/test lane remain distinct; iOS/device evidence remains separate. The 27 unmatched rows, 523 synthetic boundary mismatches and untested platforms prevent any full-parity claim.
