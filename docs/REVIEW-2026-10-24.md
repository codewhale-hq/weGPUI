## Accessibility and code review

The original AX script walked only `windows[0].uiElements[0]`. It now walks the entire first window, including titlebar siblings. Full-window dumps were collected on nine routes: tabbar, form select, switch, uploader, half-screen dialog, dialog, picker, textarea and slider.

Roles and values are exposed, but picker/select option labels are absent from the dump and controls behind modal dialogs remain accessible in the tree. AX inspection is not a VoiceOver test. VoiceOver, TalkBack, Windows screen readers and Linux assistive technologies remain untested. The Pinyin input source was restored after the composition experiment; the successful textarea case does not qualify every IME operation or single-line input.

Review of `src/` found no explicit `unsafe`, `unwrap()`, `expect()`, `panic!`, `todo!` or `unimplemented!` occurrences. This does not exclude panics from indexing, dependency APIs or invalid caller inputs. Unresolved correctness/API findings are listed in [STATUS](STATUS.md), rather than hidden in a handoff.

## Platform feasibility and weui.js scope

The pinned `gpui-pre-platform 0.3.7` source selects macOS, Windows, Linux/FreeBSD and wasm backends. It has no native iOS/Android branch in `current_platform`. This is a source-level obstacle, not a cross-compilation result. The project currently enables only `font-kit`; the pinned GPUI README requires `wayland` or `x11` for Linux desktop windows. Native Linux and Windows execution have not been verified.

The requested destination is mobile **and** desktop. Acceptance must cover macOS, Windows, Linux, iOS and Android explicitly, including real touch/soft-keyboard behaviour. A narrow desktop viewport is only visual evidence. Mobile architecture and dependency changes need a concrete feasibility proposal and owner approval before changing the exact GPUI pin or adding dependencies.

[weui.js](https://github.com/Tencent/weui.js) is a separate JavaScript wrapper project. The pinned CSS package's example shell imports weui.js 1.2.17; picker examples invoke `weui.picker` and `weui.datePicker`. Those invoked behaviours belong in example parity. Implementing the entire imperative JS API, form-validation engine or upload transport is a separate scope decision; this review did not build it.
