# Localisation and right-to-left support

weGPUI ports WeUI, whose labels were written in Chinese. The library works in English and in any
other language: every default string it draws or announces comes from a message catalog chosen
at run time, layouts follow the text direction of the active locale, and text input is built for
every script the platform can shape. This document says what exists, how to use it and what is
still unproven. Evidence for each claim is in the linked receipts; nothing here is a screen-reader
or native-speaker acceptance.

## What is localised

Only strings the library supplies itself. Text you pass to a builder (`Button::new("Save")`,
`Switch::label("Wi-Fi")`, `Cell::title(..)`) is used exactly as given.

| Kind | Examples | Source |
| --- | --- | --- |
| Default accessible names | checkbox, switch, progress, close/back/clear buttons, image viewer, message icons | `Messages` fields |
| Default visible labels | picker OK / close, search placeholder and Cancel, select Cancel, verification-code button and countdown | `Messages` fields |
| Descriptions | disabled, loading, read only, swipe row open/closed, uploader hint | `Messages` fields |
| Composed names | steps ("Step 2 of 4, Title, completed"), date field, uploader header | `Messages::join`, `fill` |
| Validation messages | date format, impossible date, hour/minute, year range | `Messages` fields |
| Picker date rows | year, month names, day labels | `Messages::year_label`, `months`, `day_label` |

## Quick start

```rust
use wegpui::{I18n, Locale, Messages};

wegpui::init(cx);                                      // installs English
I18n::set_locale(Locale::parse("ja").unwrap(), cx);    // a built-in catalog; windows redraw
```

`Locale::parse` accepts BCP 47 (`zh-Hant-TW`) and POSIX (`zh_CN.UTF-8`) spellings. The library
does not guess the user's language: your application resolves it (operating-system setting,
its own preference, `LANG`) and passes it in; a resolved tag such as `en` or `zh-Hans` can be
forwarded unchanged.

### Built-in catalogs

`I18n::set_locale` picks the catalog from the locale (`Locale::catalog_tag`); a locale without
one uses English.

| Tag | Language | Script | Direction | Review state |
| --- | --- | --- | --- | --- |
| `en` | English (default) | Latin | LTR | authored with the library |
| `zh-Hans` | Simplified Chinese | Han | LTR | reproduces the original WeUI wording |
| `zh-Hant` | Traditional Chinese | Han | LTR | starter translation |
| `ja` | Japanese | Han + Kana | LTR | starter translation |
| `ko` | Korean | Hangul | LTR | starter translation |
| `es`, `fr`, `de`, `pt` | Spanish, French, German, Portuguese | Latin | LTR | starter translations |
| `ru` | Russian | Cyrillic | LTR | starter translation |
| `hi` | Hindi | Devanagari | LTR | starter translation |
| `th` | Thai | Thai | LTR | starter translation |
| `ar` | Arabic | Arabic | RTL | starter translation |
| `he` | Hebrew | Hebrew | RTL | starter translation |

"Starter translation" means written by the maintainers' tooling and not reviewed by a native
speaker. Corrections are welcome as pull requests.

### Any other language

Switch to the closest locale, then replace what you need. Start from English so a missing field
is never blank:

```rust
I18n::set_locale(Locale::parse("sv").unwrap(), cx);   // no catalog: English, LTR
I18n::set_messages(
    Messages {
        ok: "OK".into(),
        cancel: "Avbryt".into(),
        close: "Stäng".into(),
        ..Messages::en()
    },
    cx,
);
```

`I18n::set_locale` discards a previously installed catalog; call `set_messages` after it.
`I18n::set_direction(Some(Direction::Rtl), cx)` forces a direction, `None` follows the locale.
Templates use `{name}` placeholders (listed on each `Messages` field); `fill` expands them and
`Messages::join` joins name parts with the language's separator (`", "`, `"，"`, `"、"`, `"، "`).

### Adding a built-in catalog

Add a function to `src/i18n/catalogs.rs` that invokes `catalog!` (a missing field is a compile
error), list its tag in `TAGS` and in `builtin`, and run `cargo test`: the catalog test checks
that every field is filled, every template keeps its placeholders and the twelve month names are
distinct.

## Right-to-left layout

`I18n::direction` is the direction of the active locale (Arabic, Hebrew, Persian, Urdu and the
other right-to-left scripts) unless `I18n::set_direction` forces one. Components read it when they
render and mirror themselves: rows run from the right, the leading edge is the right edge, and
arrows, back/forward icons and swipe directions flip. Nothing needs to be passed to a component.

Mirrored today: `Cell`/`Cells`, `Button`, `Dialog`, `ActionSheet` (Android skin), `NavBar`,
`TabBar`, `Switch`, `Checkbox`, `Radio`, `Agree`, `Slider`, `Progress`, `Select`, `SearchBar` and
its results, `Form`/`FormCell`/`FormGroup`/`TipsGroup`/`ClearableInput`, `Picker` (columns and the
selection band), `HalfScreenDialog` header slots, `InformationBar` and `ListTips`, `Steps` (all
four layouts), `FormPreview`, `Panel`/`MediaBox`, `Grid`, `Uploader`, `SwipedCell` (actions side,
drag direction and arrow keys), `ArticleList`, `Footer`, `LoadMore`, `Msg`, `TextArea`'s counter,
the verification-code button and the `Icon` set (arrow glyphs mirror themselves).

Application code uses the same vocabulary through [`wegpui::logical::Logical`], which adds
`row`, `ps`/`pe` (padding), `ms`/`me` (margin), `inset_s`/`inset_e` and `text_start`/`text_end` to
any GPUI element:

```rust
use wegpui::{I18n, logical::Logical};

let dir = I18n::get(cx).direction();
div().flex().row(dir).me(dir, px(16.)).text_start(dir).child(icon).child(label)
```

GPUI's flexbox treats `justify_end` as the physical right edge even in a reversed row; use
`justify_start` for the end of a right-to-left row (the library does).

### Text input

`TextInput` shapes every script the platform can shape. In a right-to-left locale a single-line
field right-aligns its text, the arrow keys follow the visual direction, and the caret, hit
testing and selection follow bidirectional runs: selecting across `Hello 2026 שלום` highlights
the visual spans of the selected characters, not one box. Emoji and combining marks move as one
grapheme cluster.

## Using the gallery

```sh
cargo run --example gallery                       # English
cargo run --example gallery -- --lang ar          # Arabic, mirrored
cargo run --example gallery -- --lang ja --dir rtl
```

The gallery opens in English; the Language menu switches the language at run time. `--lang
zh-Hans` reproduces the upstream wording that `scripts/capture.py` and `scripts/drive.py` use for
parity captures (both pass it explicitly). Demo text exists in English and Simplified Chinese;
other languages show English demo text with the library's own strings in that language. The
*Languages* page shows every script and the active catalog, and its *Try typing* group holds
editable fields for each script.

## Limits

These are the known gaps. Each is a limit of this implementation, not a decision.

- **Digits, calendars, dates.** Numbers are ASCII digits; dates are Gregorian, typed as
  `YYYY-MM-DD`, and the date picker keeps year-month-day column order in every locale. There is
  no CLDR data, plural selection or localised number format. Messages are worded to avoid
  plural-sensitive forms.
- **Wrapped text in some scripts.** GPUI breaks lines at spaces for Latin, Cyrillic, Bengali and,
  since the owner-approved change of 2026-10-25, Arabic, Hebrew, Devanagari and Greek
  ([receipt](receipts/gpui-word-break-20261025/README.md)). Thai and Hangul still break between
  any two characters: Thai needs a word dictionary and Hangul was left alone by decision.
  The approved step 2 prototype wraps right-to-left/mixed paragraphs in logical order on the
  supplied macOS captures. **Linux rendering remains limited:** Xvfb captures still clip and misalign
  Arabic/Hebrew paragraphs; the pre-step-2 A/B build also clips them. See the
  [receipt](receipts/gpui-logical-wrap-20261025/README.md) and
  [proposal status](proposals/gpui-text-i18n/README.md). Windows remains untested. Break metrics
  come from the whole paragraph, so a reshaped row can exceed its width slightly; styled runs,
  underline and strikethrough in wrapped right-to-left rows are unverified.
- **Multi-line input in right-to-left locales.** A `TextArea` does not right-align its text, and
  its caret and selection follow bidirectional runs only on lines that are not soft-wrapped.
- **Helpers that cannot see the direction.** `form::cell_control` and `cell_control_flex` keep a
  physical 16 px left margin, `half_screen_dialog::action_group` lays children out in call order
  from the left, and `Button`'s `margin`/`padding` take physical left/right values, as does
  `Modal`'s safe-area padding. Pass the values you need for the active direction.
- **Label column.** `FormCell` labels are at most 85 px wide, as upstream, and a longer
  translated label wraps inside the word. Use short labels or the vertical layout.
- **Agree text.** The independent completion continuation lets long text shrink and wrap
  while preserving checkbox width ([receipt](receipts/completion-20261025/README.md)). Full
  multilingual and cross-platform acceptance remains open; the English gallery sample stays short.
- **No automatic locale detection.** Adding a platform-locale dependency needs a maintainer
  decision; applications already have this.
- **Unreviewed translations.** Twelve of the fourteen catalogs are starter translations. Screen
  reader pronunciation and native-speaker review are open.

## Where the evidence is

[`receipts/i18n-20261025`](receipts/i18n-20261025/README.md) records the source, host, gates,
captures and what each does not show; [`receipts/gpui-word-break-20261025`](receipts/gpui-word-break-20261025/README.md)
covers the vendored word-break change. The
[`logical-wrap` receipt](receipts/gpui-logical-wrap-20261025/README.md) records the step 2
prototype, passing source gates and the Linux visual failure that led to the initial landing hold.
The later [publication review](REVIEW-2026-10-26.md) records authorization to commit the existing
prototype with its limits; full localisation acceptance and step 3 remain open. Unit tests cover the catalogs and the bidirectional
caret maths; captures cover every route in English, mirrored layouts in Arabic, every script's
shaping, and bidirectional selection. Screen-reader behaviour in other languages, real keyboard
and IME input in a right-to-left field, other platforms and a native-speaker review have not been
tested.
